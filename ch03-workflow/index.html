日常版更與推送流程

這章節會帶你走過每一天最常用的「版更與推版」標準作業流程 (SOP)。

標準的 VSCode 推送流程 (Daily Workflow)

當你完成了一個段落的程式碼，準備進行「版更」並推送到 GitHub 時，請依循以下步驟：

  1. 存檔：確認 VSCode 內的檔案都已存檔 (快捷鍵 Ctrl + S)。
  2. 檢視變更：切換到 Source Control 面板，檢查有哪些檔案被修改。
  3. 暫存 (Stage)：點擊 Changes 區塊右上角的 + 號，一次將所有變更放入暫存區 (Staged Changes)。
  4. 提交 (Commit)：
    • 寫清楚這版更新了什麼內容。建議使用簡單的前綴：
      • feat: (新增功能)
      • fix: (修復 Bug)
      • docs: (文件更新)
      • style: (排版與格式化)
    • 按下 ✓ 按鈕或點擊 Commit。
  5. 同步 / 推送 (Sync / Push)：
    • 提交完成後，面板上會出現 Sync Changes (同步變更) 按鈕，點擊它即可將本地的更新推送到 GitHub。
    • 如果遠端有別人的更新，它也會一併拉取 (Pull) 下來。

常見狀況與最佳實踐

1. 忽略不需要版控的檔案 (.gitignore)

  • 有些檔案 絕對不應該 上傳到 Git，例如：
    • node_modules/ (套件庫)
    • .env, .env.local (機密金鑰與環境變數)
    • 作業系統快取如 .DS_Store
    • 打包產物如 dist/, build/
  • 強制規範：所有專案必須包含 .gitignore 檔案。如果發現在 Changes 列表裡出現這些檔案，請在專案根目錄修改或建立 .gitignore 檔案，並將要忽略的資料夾/檔案名稱寫入。

2. 遇到合併衝突 (Merge Conflicts)

  • 當你與遠端儲存庫的同一份檔案的同一行程式碼有不同的修改時，VSCode 會提示發生衝突。
  • 檔案內會出現高亮區塊，讓你選擇：
    • Accept Current Change (保留你本地的變更)
    • Accept Incoming Change (保留遠端的變更)
    • Accept Both Changes (兩者都保留，稍後手動修改)
  • 選擇完畢並存檔後，重新 Stage + 並 Commit 即可解決衝突。
